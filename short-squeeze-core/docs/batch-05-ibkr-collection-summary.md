```
artifact_format                 = CSV        bar_interval = 1_MINUTE
event_timezone                  = UTC        timestamp_semantics = START
session_coverage                = EXTENDED (useRTH=0)
data_time_basis                 = HISTORICAL value_authenticity = VENDOR_SUPPLIED
price_adjustment_semantics      = UNKNOWN
volume_adjustment_semantics     = UNKNOWN
corporate_action_handling       = UNKNOWN
```

Because IBKR TRADES adjustment status and US-stock volume unit (shares vs lots) are not
verifiable from the allowed non-account API surface, adjustment/volume semantics are
declared `UNKNOWN`. The Batch 03 normalizer treats this as `MISSING_ADJUSTMENT_SEMANTICS`
(fatal), so **all 26 preflights are `PREFLIGHT_REJECTED`** — the honest result, not forced
to `READY`. Batch 03 semantics were not weakened.

## Limitations (must read before any future use)

1. **Weekend boundary / forward window has no native trading.** The frozen boundary
   `2026-07-18T13:37:55Z` is a **Saturday**; the `FROZEN_FORWARD_24H` window
   (Sat 13:37:55Z → Sun 13:37:55Z) is entirely non-trading.
2. **IBKR substituted the most-recent-available session for both requests.** For every
   symbol, both `DETECTION_CONTEXT_PRECEDING_24H` and `FROZEN_FORWARD_24H` returned the
   **same** bar count and the **same** coverage `2026-07-16T16:00:00Z →
   2026-07-17T23:59:00Z` (Thursday–Friday). When an `endDateTime` falls on a non-trading
   day, IBKR returns bars ending at the last available trading moment rather than an empty
   set. The tool recorded exactly what the provider returned and did **not** reinterpret,
   reshift, or broaden any request.
3. **Returned coverage does not equal the requested window.** Neither returned block
   matches its intended `[start, end)` slice: the detection window returned data starting
   before its requested start (`Thu 16:00Z`), and the forward window returned
   **pre-boundary Friday data**, not weekend data. The `FROZEN_FORWARD_24H` artifacts
   therefore **must not** be treated as forward-outcome evidence.
4. **No `SUCCESS_EMPTY` occurred** because IBKR never returned an empty set; the
   `SUCCESS_EMPTY` / `PREFLIGHT_NOT_APPLICABLE_EMPTY` paths remain exercised only by tests.
5. **Whole-second truncation:** the fractional-second boundary (`.017661`) was truncated to
   whole seconds for the API `endDateTime`; `REQUEST_TIME_PRECISION_TRUNCATED_TO_SECOND` is
   recorded on every request.
6. **No outcomes, no association.** `DETECTION_CONTEXT` / `FROZEN_FORWARD` labels are source
   organization only. No case association, reference price, return, ±25% crossing, or
   squeeze classification was computed.
