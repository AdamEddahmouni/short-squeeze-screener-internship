# Phase 2D Progress

Phase 2D is implemented on `phase/2d-evidence-alignment-readiness` as a local-only,
deterministic cross-domain evidence-alignment and readiness-diagnostics layer built directly on
Phase 1's `PointInTimeEvidenceBundle` (not on raw observations) and, optionally, already-computed
Phase 2A/2B/2C metric results.

## Delivered

- `readiness.models` — seven standalone frozen result models (`DomainCoverageSnapshot`,
  `EvidenceAgeAlignment`, `ReportingPeriodAlignment`, `EvidenceConflictSummary`,
  `EvidenceMissingnessSummary`, `InputSufficiencyResult`, `EvidenceReadinessSnapshot`) plus
  `OperationRequirementPolicy`/`DomainRequirement`, reusing `Quality`/`QualityState` and
  `DiagnosticSeverity` verbatim rather than inventing new ones
- `readiness.identifiers` — deterministic IDs reusing Phase 2A's existing `METRIC_NAMESPACE`
  **and** its existing `deterministic_metric_id()` function directly; every identity dict opens
  with a literal `result_type` string preventing cross-model collision
- `readiness.diagnostics` — `ReadinessDiagnosticCode`/`ReadinessDiagnostic`, only codes an
  actually-implemented path emits
- `readiness.policies` — versioned (`phase_2d_readiness_policy.v1`), declarative
  `OperationRequirementPolicy` registry for all 17 named operations from the handoff
- `readiness.coverage` — `DomainCoverageState` classification
  (`PRESENT/MISSING/UNAVAILABLE/CONFLICTED/CANCELLED/PARTIAL/UNKNOWN`) with justified precedence
  over `PointInTimeEvidenceBundle.source_coverage`/`diagnostics`/`conflicts`/`observations`
- `readiness.age_alignment` / `readiness.reporting_alignment` — cross-domain availability-age
  and reporting-period-age alignment, both reusing `metrics.source_age.build_source_age`
  directly, never mixed into one number (ADR 0039)
- `readiness.conflicts` / `readiness.missingness` — deterministic groupings over existing
  evidence facts, excluding `TEMPORAL_DIFFERENCE` conflicts (a bug found and fixed during
  testing — see below) and distinguishing missing/unknown/conflicted/insufficient-history
- `readiness.sufficiency` / `readiness.snapshot` — operation-scoped
  `SUFFICIENT/INSUFFICIENT/UNKNOWN/CONFLICTED` resolution (ADR 0038, ADR 0040), never
  recomputing a downstream metric
- `build-evidence-readiness` CLI subcommand — local files only, stable canonical-JSON output,
  nonzero exit on an unsupported operation or policy version
- 138 new tests across `tests/readiness/` (models, policies, coverage, age alignment, reporting
  alignment, conflicts, missingness, sufficiency, snapshot, anchors) and
  `tests/compatibility/test_phase_2d_isolation.py` (14 tests)
- a separate Phase 2D anchor manifest
  (`tests/fixtures/readiness/expected_phase_2d_readiness_metadata.json`, 32 anchors, never
  merged into the Phase 1/2A/2B/2C manifests) regenerated byte-identically across multiple runs
- ADRs 0038-0040; `evidence-readiness-contract.md`, `domain-coverage-semantics.md`,
  `evidence-age-alignment-semantics.md`, `reporting-period-alignment-semantics.md`,
  `input-sufficiency-semantics.md`, `conflict-and-missingness-summary-semantics.md`

## Bugs found and fixed during test-first development

1. **Temporal-difference conflicts incorrectly counted.** The initial `classify_domain_coverage`
   and `build_conflict_summary` treated every `EvidenceConflict` in a domain's observation set as
   a real conflict, including `TEMPORAL_DIFFERENCE`-classified entries, which Phase 1 explicitly
   documents as "not a real conflict" (compatible field, different comparison period). Caught by
   `test_active_record_plus_older_cancellation_of_different_period_is_present`, which unexpectedly
   returned `CONFLICTED`. Fixed by excluding `ConflictClassification.TEMPORAL_DIFFERENCE` from
   both modules' conflict checks, matching Phase 1's own `CoverageState` computation.
2. **Anchor-script registry mutation leaking across the test session.** The
   `incompatible_borrow_fee_units` anchor temporarily registered a script-local test policy into
   the shared `OPERATION_REQUIREMENT_POLICIES` dict and never removed it, causing
   `test_all_seventeen_operations_registered` to see 18 operations when the anchor tests ran
   first in the same pytest process. Fixed with a `try/finally` cleanup.

## Reuse, not reimplementation

No Phase 1/2A/2B/2C file was modified except `src/squeeze_core/__main__.py` (new subcommand
branch). Every file under `evidence/`, `contracts/`, `adapters/`, `replay/`, `serialization/`,
and `metrics/` is byte-identical to the Phase 2C completion commit (`61b15ab3`), verified by
`tests/compatibility/test_phase_2d_isolation.py`. `readiness/` consumes
`PointInTimeEvidenceBundle`, `MetricResult`/`NormalizedMetricResult`/`PressureMetricResult`,
`build_source_age`, `decimal_mean`, `METRIC_NAMESPACE`/`deterministic_metric_id`, and
`canonical_json`/`canonical_hash` — all imported, none duplicated.

## Documented scope decisions

- Fixtures for the larger edge-case matrix live in `tests/readiness/conftest.py` factory
  functions rather than redundant JSON files (documented in
  `tests/fixtures/readiness/phase_2d_fixture_metadata.json`); every required case family from
  the handoff has at least one representative named test, though not every one of the ~190
  individually-numbered handoff bullets has its own dedicated test function — related cases are
  consolidated where the underlying code path is identical.
- `MISSING_REQUIRED_FIELD` is not implemented as a distinct missingness category in this phase
  (`docs/conflict-and-missingness-summary-semantics.md`); per-field value missingness remains
  each metric builder's own responsibility (the established Phase 2C pattern), consistent with
  Phase 2D operating at domain/metric granularity.
- Unit-incompatibility detection operates on referenced metric results, not raw observations,
  since canonical payload models normalize units away at the adapter boundary
  (`docs/input-sufficiency-semantics.md`).
- `AgeDimension` has two members, not the six suggested in the handoff; only availability age
  and reporting-period age have an existing, tested, cross-domain-comparable computation
  (ADR 0039).
