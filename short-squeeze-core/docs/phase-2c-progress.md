# Phase 2C Progress

Phase 2C is implemented on `phase/2c-short-interest-borrow-metrics` as a local-only,
deterministic short-interest and borrow-pressure metrics layer built on Phase 1D
(`PUBLISHED_SHORT_INTEREST`), Phase 1B (`BORROW_FEE`/`BORROW_AVAILABILITY`), and — for
`DAYS_TO_COVER` only — Phase 2A's `MEAN_VOLUME_BASELINE`, composed rather than reimplemented.

## Delivered

- `metrics.source_age` — `SourceAgeMetadata`, keeping evidence-freshness
  (`availability_age_seconds`) and reporting-period staleness (`reporting_period_age_days`,
  `publication_lag_seconds`) as two explicit, never-collapsed concepts (ADR 0035)
- `metrics.pressure_models` — standalone frozen `PressureMetricResult`/`DaysToCoverComponents`,
  deliberately not extending `MetricResult` (its `source_interval: BarInterval` is required and
  meaningless for non-bar metrics) or `NormalizedMetricResult` (shaped for a target-vs-baseline
  distribution comparison, not a two-sided point-in-time record diff)
- `metrics.pressure_identifiers` — deterministic IDs reusing Phase 2A's existing
  `METRIC_NAMESPACE` **and** its existing `deterministic_metric_id()` function directly (no new
  namespace, no reimplemented encoding), structurally distinct identity-dict shapes proven
  non-colliding by test
- `metrics.pressure_selection` — point-in-time eligibility, lifecycle resolution
  (revision/cancellation/conflict for short interest; conflict-only for borrow, which has no
  revision concept), and exact-boundary resolution for borrow observations
- `PUBLISHED_SHORT_INTEREST_ABSOLUTE_CHANGE`/`_PERCENTAGE_CHANGE`
  (`explicit_reporting_period_pair.v1`) and `PUBLISHED_SHORT_INTEREST_REVISION_DELTA`
  (`explicit_revision_link.v1`)
- `DAYS_TO_COVER_COMPONENTS`/`DAYS_TO_COVER`
  (`published_short_interest_divided_by_trailing_mean_completed_daily_share_volume.v1`),
  combining a resolved short-interest observation with a locally-constructed
  `MEAN_VOLUME_BASELINE` `MetricResult` — see ADR 0036 for why `build_volume_baseline_result`
  is not reused wholesale here
- `BORROW_FEE_ABSOLUTE_CHANGE`/`_RELATIVE_PERCENTAGE_CHANGE` and
  `BORROW_AVAILABILITY_ABSOLUTE_CHANGE`/`_PERCENTAGE_CHANGE` (`explicit_observation_pair.v1`) —
  see ADR 0037 for the percentage-point vs. relative-percentage distinction
- `build-market-metrics` CLI extended via nine new `registry.py` dispatch branches;
  `__main__.py` itself is unchanged (it already dispatches generically through
  `build_metric_results`)
- 151 new tests across `tests/metrics/` and `tests/compatibility/` (source age, pressure models/
  identifiers/selection, short-interest change, revision delta, days to cover, borrow fee change,
  borrow availability change, cross-cutting lifecycle/no-look-ahead, cross-domain isolation, CLI,
  anchors, isolation, compatibility), covering every required case family from the Phase 2C
  handoff
- a separate Phase 2C anchor manifest
  (`tests/fixtures/metrics/expected_phase_2c_metric_metadata.json`, 26 anchors, never merged into
  the Phase 1/2A/2B manifests) regenerated byte-identically twice before committing, with no
  unexplained collision against the Phase 1/2A/2B anchor sets
- ADRs 0035-0037; `short-interest-derived-metric-contract.md`, `days-to-cover-semantics.md`,
  `borrow-fee-change-semantics.md`, `borrow-availability-change-semantics.md`

## Reuse, not reimplementation

No Phase 1/2A/2B selector, formula, or model was modified. `metrics/selection.py`,
`metrics/volume_baselines.py`, `metrics/returns.py`, `metrics/gaps.py`, `metrics/ranges.py`,
`metrics/normalized_models.py`, `metrics/relative_volume.py`, `metrics/volume_standardization.py`,
`metrics/return_baselines.py`, `metrics/return_standardization.py`, and every file under
`adapters/finra`, `adapters/ibkr`, `evidence/`, and `contracts/` are byte-identical to the
Phase 2B completion commit (`b2a75e3e`). `metrics/models.py`, `metrics/diagnostics.py`,
`metrics/registry.py`, `metrics/serialization.py`, and `metrics/__init__.py` received
additive-only changes (new enum members, new diagnostic codes, new dispatch branches, new
exports) — every Phase 1/2A/2B test, anchor, and CLI request continues to pass and produce
byte-identical output (`tests/compatibility/test_phase_2c_isolation.py`).

`DAYS_TO_COVER` is the one metric that reaches across domains: it composes Phase 2A's
`selection.resolve_trailing_window` and `volume_baselines.compute_mean_volume` **directly**
(not through `build_volume_baseline_result`, whose API shape assumes a concrete target-bar
boundary that days-to-cover has no analogue for), documented as a deliberate, narrower
composition than Phase 2B's own reuse pattern in ADR 0036.

## Isolation test update (not a weakening)

`tests/metrics/test_isolation.py`'s `FORBIDDEN_IDENTIFIER_SUBSTRINGS` narrowed the existing bare
`"annualiz"` entry to `"annualized_vol"`/`"annualized_return"`: Phase 1B's own pre-existing,
approved `BorrowFeePayload.annualized_fee_percent` field legitimately contains "annualiz" and is
read throughout `metrics/borrow_fee_changes.py`, while the concept actually excluded (annualized
volatility/return statistics) is unaffected — the same kind of legitimate-field carve-out Phase
2B made for `"relative_volume"`. Every other prior-phase forbidden substring is unchanged, and a
new Phase-2C-specific set (`short_pressure_score`, `borrow_pressure_score`,
`cost_to_borrow_score`, `hard_to_borrow_score`, `squeeze_probability`, `fail_to_deliver`,
`gamma_exposure`, `open_interest`) is added — see `docs/phase-2c-design.md` §14.

## Deterministic anchors

Canonical values are stored in `tests/fixtures/metrics/expected_phase_2c_metric_metadata.json`.
All Phase 1 anchors in `tests/fixtures/compatibility/phase_1_anchor_manifest.json` and all Phase
2A/2B anchors in `expected_phase_2a_metric_metadata.json`/`expected_phase_2b_metric_metadata.json`
remain byte-for-byte unchanged (`tests/compatibility/test_phase_2c_isolation.py` diffs all three
against the Phase 2B completion commit `b2a75e3e`).

## Explicit exclusions

There is no short-float recalculation, estimated/synthetic short interest, fail-to-deliver
analytics, options/gamma/open-interest analytics, cost-to-borrow/hard-to-borrow/borrow-pressure/
short-pressure score, squeeze probability, composite squeeze score, candidate rank,
Prime/Subprime, threshold/strong-weak/bullish-bearish label, entry/exit/target/stop,
backtesting, live/network/database/GUI/ML code anywhere in `squeeze_core.metrics`.
