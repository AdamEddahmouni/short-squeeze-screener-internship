# Phase 2B Progress

Phase 2B is implemented on `phase/2b-normalized-market-activity` as a local-only, deterministic
normalized-market-activity layer built on top of Phase 2A's foundational metrics and Phase 1H
`MARKET_BARS` evidence, composed rather than reimplemented.

## Delivered

- `metrics.statistics` — exact `Decimal` population mean/variance/standard-deviation/sqrt under a
  local `localcontext(prec=50)` guard, no `float`, no `numpy`/`scipy`/`statistics`-module call
- `metrics.normalized_models` — standalone frozen `BaselineStatistics`/`NormalizedMetricResult`/
  `ReturnCountWindow`/`StandardDeviationPolicy`/`BaselineKind` models, deliberately not extending
  Phase 2A's `MetricResult` (would change every already-anchored Phase 2A result's bytes)
- `metrics.normalized_identifiers` — deterministic IDs under Phase 2A's own `METRIC_NAMESPACE`,
  structurally distinct identity-dict shapes proven non-colliding by test
- `RELATIVE_VOLUME`/`VOLUME_PERCENT_DEVIATION` (`trailing_mean_ratio.v1`), built directly on Phase
  2A's `build_volume_baseline_result` — ADR 0031's deferred "numerator-comparison half"
- `VOLUME_Z_SCORE` (`volume_distribution_z_score.v1`), standardizing target volume against a
  population-stddev distribution built from the same selector `MEAN_VOLUME_BASELINE` uses
- `MEAN_PERCENTAGE_RETURN_BASELINE`/`PERCENTAGE_RETURN_STANDARD_DEVIATION_BASELINE`
  (`adjacent_close_to_close_return_count.v1`), both reading one shared internal
  `BaselineStatistics(baseline_kind=PERCENTAGE_RETURN)`
- `PERCENTAGE_RETURN_Z_SCORE` (`return_distribution_z_score.v1`), combining a target
  `PERCENTAGE_RETURN` (Phase 2A's own `build_return_result`) with the return-distribution baseline
- `population_standard_deviation_decimal.v1` — the sole `StandardDeviationPolicy`; ADR 0033
  explains the population-vs-sample choice
- target exclusion from every baseline/distribution, hard-coded (not caller-toggleable) — ADR 0034
- `build-market-metrics` CLI extended via six new `registry.py` dispatch branches;
  `__main__.py` itself is unchanged
- 158 new tests across `tests/metrics/` and `tests/compatibility/` (statistics, normalized models,
  normalized identifiers, relative volume, volume standardization, return baselines, return
  standardization, cross-cutting lifecycle/no-look-ahead, CLI, anchors, isolation, compatibility),
  covering every required case family from the Phase 2B handoff
- a separate Phase 2B anchor manifest
  (`tests/fixtures/metrics/expected_phase_2b_metric_metadata.json`, twenty-one anchors, never
  merged into the Phase 1 or Phase 2A manifests) regenerated byte-identically twice before
  committing, with no unexplained collision against the Phase 2A anchor set
- ADRs 0032-0034; `normalized-market-activity-contract.md` and per-metric semantics docs

## Reuse, not reimplementation

No Phase 2A selector, formula, or model was modified. `metrics/selection.py`, `metrics/returns.py`,
`metrics/volume_baselines.py`, `metrics/gaps.py`, and `metrics/ranges.py` are byte-identical to the
Phase 2A completion commit. `metrics/models.py`, `metrics/diagnostics.py`, `metrics/registry.py`,
`metrics/serialization.py`, and `metrics/__init__.py` received additive-only changes (new enum
members, new diagnostic codes, new dispatch branches, new exports) — every Phase 2A test, anchor,
and CLI request continues to pass and produce byte-identical output.

One deliberate exception to pure composition: return baselines cannot reuse
`selection.resolve_trailing_window` directly, because that selector's missing-volume/unit-mismatch
filtering is volume-specific and would incorrectly exclude a bar missing `volume` even though a
return baseline only needs `close`. A small, separate price-only trailing-bar walk
(`return_baselines._resolve_price_trailing_bars`) reuses `selection.py`'s private boundary-grouping
and lifecycle-resolution helpers directly rather than duplicating their logic — the same
"duplicate a small private helper rather than change the shared module's public surface" tradeoff
ADR 0030 already accepted for `_metadata_time`.

## Isolation test update (not a weakening)

`tests/metrics/test_isolation.py`'s `FORBIDDEN_IDENTIFIER_SUBSTRINGS` previously forbade
`"relative_volume"` and `"rvol"` — a Phase-2A-only guarantee (ADR 0031 deferred the concept, it did
not ban it). Phase 2B's handoff explicitly requires `RELATIVE_VOLUME` as a descriptive, non-scored
metric, so `"relative_volume"` is removed from the forbidden set; `"rvol"` remains forbidden per the
handoff's own instruction ("Do not call this 'RVOL signal.'"). Every other forbidden substring
(`moving_average`, `bollinger`, `candidate_score`, `recommendation`, `paper_trade`, etc.) is
unchanged, and a new Phase-2B-specific set (`squeeze_score`, `weekly_volatility`, `sharpe`,
`true_range`, `ewma`, `percentile`, `median_absolute_deviation`, ...) is added — see
`docs/phase-2b-design.md` §14 and ADR 0032.

## Deterministic anchors

Canonical values are stored in
`tests/fixtures/metrics/expected_phase_2b_metric_metadata.json`. All Phase 1 anchors in
`tests/fixtures/compatibility/phase_1_anchor_manifest.json` and all Phase 2A anchors in
`tests/fixtures/metrics/expected_phase_2a_metric_metadata.json` remain byte-for-byte unchanged
(`tests/compatibility/test_phase_2b_isolation.py` diffs both against the Phase 2A completion commit
`d776e30e`).

## Explicit exclusions

There is no relative-volume ranking/category/"unusual volume" label, dollar volume, turnover,
volume acceleration/slope/momentum/percentile, return percentile, robust z-score, median absolute
deviation, EWMA, rolling Sharpe, annualized/realized volatility, ATR, true range, moving average,
Bollinger/Keltner channel, TTM Squeeze, RSI, MACD, breakout/trend/gap classification, candlestick
pattern, order-flow/aggressor-side metric, sentiment, catalyst classification, candidate
score/rank/Prime-Subprime, recommendation, alert, entry/exit/target/stop, backtesting,
live/network/database/GUI code, or machine learning anywhere in `squeeze_core.metrics`.
